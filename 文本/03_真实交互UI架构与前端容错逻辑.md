# 真实交互 UI 架构与前端容错逻辑

WeightHelper 的前端 UI 架构（React + Vite）摒弃了繁文缛节，以 `BottomNav.jsx` 为中枢，将整个应用的复杂度收敛在几个极其清晰的组件树中。

## 1. 极简组件树架构

```text
App.jsx                    # 主入口，全局状态管理（token/goal/timezone）
├── Auth.jsx               # 轻量级鉴权页（登录/注册）伴随新用户弹窗卡片
├── BottomNav.jsx          # 底部导航中枢（记录/足迹/设置）
├── CameraCapture.jsx      # 核心输入页：拍照/图片上传
├── AIAnalyzer.jsx         # 异步处理页：AI 分析中的过渡动画
├── NutritionCard.jsx      # 核心展现页：识别结果与滑动调份数
├── HistoryList.jsx        # 数据沉淀页：跨时区饮食日历追踪
├── Settings.jsx           # 全局配置页：卡路里目标与时区选择
└── ProPaywall.jsx         # 占位组件：为未来高级功能预留的付费墙
```

## 2. 杀手级前端交互：滑动调份数 (NutritionCard.jsx)

商业应用在 AI 识别出结果后，往往要求用户手动输入一个具体的“克数”（如 253g），这种做法完全违背了人类对食物的直觉感知。

WeightHelper 在 `NutritionCard.jsx` 中创新性地实现了**“相对比例微调逻辑”**：
1.  **AI 锚定基准值**：Gemini 识别图片后，会给出一个基于其认知的默认基准热量和营养素（设定为 1 份，或 100%）。
2.  **前端数学映射**：UI 提供了一个阻尼平滑的滑动条（或步进器），支持按照 `1/4 份`、`半份`、`1 份`、`1.5 份` 等视觉直觉进行调节。
3.  **实时重算**：用户拖动滑动条时，前端通过简单的乘法运算实时重算卡路里和宏量营养素（碳水、蛋白质、脂肪），并立即反馈在环形仪表盘上。这彻底消灭了“厨房秤焦虑”。

## 3. UI 极简风与信息降噪

针对前期版本存在的视觉噪音，最新的前端代码进行了以下深刻的“做减法”重构：
*   **去除全局浮夸指标**：删去了之前悬浮在每个页面的 AI 模型/Token 徽章。现在的处理方式极其克制——只在“记录”页面的最下方，用低对比度的字体低调展示当前正成功被调用的模型名称（如 `gemini-3.1-flash-lite`），在保持极客感的同时不干扰正常操作。
*   **剔除冗余点评**：移除了历史记录页的“AI 营养师点评”功能。事实证明，长篇大论的点评只会增加长辈的认知负担，不如单纯的数字记录来得清爽。
*   **空间松弛感**：整体调大了全站顶部的 Padding，并使用绿叶子 `icon.png` 替代了原生图标，赋予产品更强的“自然、健康”的心理暗示。

## 4. 跨时区场景的前端降级展示 (HistoryList.jsx)

既然是面向分布在北京、柏林、休斯敦的家庭成员，前端如何渲染时间成了一个大问题。
*   **渲染逻辑**：放弃单纯显示“20:00”这种容易引起误解的本地时间，而是强制替换为带有世界时钟偏移格式的绝对表达（例如 `UTC+8 09:00`）。
*   **体验价值**：当纽约的成员查看北京长辈的饮食日历时，这种明确带有 `UTC` 偏移量的展示，瞬间消除了跨越半个地球带来的认知错位。
